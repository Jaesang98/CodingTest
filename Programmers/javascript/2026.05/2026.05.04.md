## 오늘 배운 것

### 새로운 문법

**`findIndex`** — 배열에서 조건을 만족하는 **첫 번째 요소의 인덱스** 반환

- 못 찾으면 `-1` 반환 (직접 `answer = -1` 초기화하고 `for`로 돌리는 거랑 동일한 동작)

**`startsWith`** — 문자열이 특정 문자열로 **시작하는지** 검사 (true/false 반환)

- `endsWith`도 짝꿍으로 같이 기억해두자

**`slice`의 인자 1개** — 끝 인자 생략하면 **끝까지** 잘라냄

- `arr.slice(2)` → 2번 인덱스부터 끝까지

**`localeCompare`** — 문자열 비교 (정렬용). 사전순으로 비교해서 -1, 0, 1 반환

### 새로운 알고리즘 개념 ⭐

**최소공배수 공식**

```
최소공배수 = (숫자1 × 숫자2) / 최대공약수
```

> 최소공배수는 최대공약수만 알면 한 줄로 끝난다. 이거 모르면 평생 둘 다 따로 구하느라 고생함.

**유클리드 호제법** — 최대공약수를 빠르게 구하는 방법

> 큰 수를 작은 수로 나눈 **나머지**로 계속 바꿔가다가, 나머지가 0이 되면 그때 작은 수가 최대공약수.

```javascript
function gcd(a, b) {
  if (b === 0) return a;
  return gcd(b, a % b);
}

// 예: gcd(12, 18)
// → gcd(18, 12)  (18 % 12 = 6)
// → gcd(12, 6)   (12 % 6 = 0)
// → gcd(6, 0)    → 6 반환
```

내가 처음에 짠 `getMin`처럼 `min`부터 하나씩 올려가며 검사하는 방식은 숫자 커지면 매우 느림. 유클리드는 나누기 한 번으로 확 줄어드니 훨씬 빠름.

## 0단계 — 머리 회전

**소요 시간:** 30분 / **풀이 수:** 7문제

초반에 집중이 잘 안 됐는데도 30분 안에 끝남. 슬슬 "개쉬운" 건 줄어들고 **살짝 생각해야 하는 문제**가 나오기 시작함. 답이 한 가지가 아니라 **여러 풀이가 가능한 문제**도 늘어서 다른 사람 풀이 보는 재미가 생김.

### 문제: 1로 만들기 ([링크](https://school.programmers.co.kr/learn/courses/30/lessons/181898))

내 풀이:

```javascript
function solution(arr, idx) {
  var answer = -1;

  for (var i = 0; i < arr.length; i++) {
    if (i >= idx && arr[i] === 1) {
      answer = i;
      break;
    }
  }

  return answer;
}
```

> `findIndex`를 쓰면 한 줄로 끝남. 다음에 비슷한 패턴 만나면 바로 떠올리자.

```javascript
function solution(arr, idx) {
  return arr.findIndex((v, i) => i >= idx && v === 1);
}
```

### 문제: 접두사인지 확인하기 ([링크](https://school.programmers.co.kr/learn/courses/30/lessons/181906))

내 풀이:

```javascript
function solution(my_string, is_prefix) {
  my_string = my_string.replace(is_prefix, "1");
  return my_string[0] === "1" ? 1 : 0;
}
```

> `replace` + 첫 글자 검사로 우회한 풀이. 작동은 하지만 의도가 한눈에 안 들어옴. `startsWith` 쓰면 직관적임.

```javascript
function solution(my_string, is_prefix) {
  return my_string.startsWith(is_prefix) ? 1 : 0;
}
```

### 문제: 최대공약수와 최소공배수 ([링크](https://school.programmers.co.kr/learn/courses/30/lessons/12940))

**소요 시간:** 약 30~40분 (그 중 20분 막힘 → GPT 힌트)

### 풀이 흐름

| 버전 | 핵심 변화                                                       | 결과                            |
| ---- | --------------------------------------------------------------- | ------------------------------- |
| 처음 | 최대공약수는 `for` 역순, 최소공배수는 `getMin` 재귀로 직접 구함 | 테스트는 통과, 채점 **18점** ❌ |
| 2차  | 최소공배수는 공식 `(n*m)/gcd`로 변경                            | **통과** ✅                     |

---

### 처음 — `getMin` 재귀로 직접 구하기 시도

> 테스트 케이스는 다 통과했는데 제출하니 18점. 로직이 좀 이상해도 답은 맞을 줄 알았는데... 20분 정도 붙잡다가 GPT에 힌트 요청. 느낌상 `getMin`이 문제일 거 같았는데 정확히 그쪽을 짚어줌.

```javascript
function solution(n, m) {
  var answer = [getMax(n, m), getMin(n, m)];
  return answer;
}
function getMax(n, m) {
  var max = n > m ? n : m;

  for (var i = max; i >= 1; i--) {
    if (n % i === 0 && m % i === 0) {
      return i;
    }
  }
}
function getMin(n, m) {
  var max = n > m ? n : m;
  var min = n > m ? m : n;

  if (max % min === 0) {
    return max;
  }
  return getMin(min, max * 2);
}
```

**18점이 나온 이유 추측:**

- `getMin`이 `min`(작은 수)을 1씩 키우는 게 아니라 `max*2`로 계속 두 배로 키움
- 예: `n=2, m=7`이면 `getMin(2,7)` → `getMin(7,4)` → `getMin(4,14)` → `getMin(14,8)` → ... 처럼 **실제 최소공배수를 건너뛰는 케이스가 생김**
- 또는 무한 재귀에 빠지거나 스택 오버플로 가능성도 있음
- 어떤 케이스에서는 운 좋게 맞고, 어떤 케이스에서는 틀려서 부분점수만 나온 거로 추정

### 2차 (최종) — 공식 적용

```javascript
function solution(n, m) {
  var answer = [getMax(n, m), (n * m) / getMax(n, m)];
  return answer;
}
function getMax(n, m) {
  var max = n > m ? n : m;

  for (var i = max; i >= 1; i--) {
    if (n % i === 0 && m % i === 0) {
      return i;
    }
  }
}
```

> 한 줄로 끝났다. **최소공배수는 공식 하나면 끝**이라는 걸 모르면 영영 헤맸을 듯. 수학 지식이 코드 길이를 결정하는 순간.

### 더 발전시킨다면 — 유클리드 호제법

`getMax`의 `for(var i = max; i >= 1; i--)`는 숫자가 커지면 굉장히 느림. 유클리드 호제법으로 바꾸면 훨씬 빠름.

```javascript
function solution(n, m) {
  var gcd = getGCD(n, m);
  return [gcd, (n * m) / gcd];
}

function getGCD(a, b) {
  if (b === 0) return a;
  return getGCD(b, a % b);
}
```

## 오늘의 핵심 개념 정리

### 유클리드 호제법 (Euclidean Algorithm)

> 두 수 `a`, `b`의 최대공약수는, `b`와 `a % b`의 최대공약수와 같다.

**왜 빠른가?**

- 내가 짠 `for(var i = max; i >= 1; i--)` 방식은 최악의 경우 `max`번 반복
- 유클리드는 매번 숫자가 **나머지 크기로 확 줄어듦** → 반복 횟수가 로그 단위
- 예: `gcd(1000000, 999999)` → 내 방식은 100만 번 비교, 유클리드는 몇 번 만에 끝남

**동작 예시 (`gcd(48, 18)`):**

```
gcd(48, 18) → 48 % 18 = 12 → gcd(18, 12)
gcd(18, 12) → 18 % 12 = 6  → gcd(12, 6)
gcd(12, 6)  → 12 % 6  = 0  → gcd(6, 0)
gcd(6, 0)   → 6 반환 ✅
```

### `findIndex` vs `for` + `break`

| 방식            | 코드  | 못 찾으면          |
| --------------- | ----- | ------------------ |
| `for` + `break` | 6~7줄 | `-1` 직접 초기화   |
| `findIndex`     | 1줄   | 자동으로 `-1` 반환 |

> 조건 만족하는 **첫 인덱스**가 필요하면 `findIndex`. **첫 요소 자체**가 필요하면 `find`.

### `startsWith` / `endsWith`

```javascript
"hello world".startsWith("hello"); // true
"hello world".endsWith("world"); // true
```

> 접두사·접미사 검사할 때 `replace` 트릭 쓰지 말고 이거 쓰자. 의도가 명확함.
